1 Problem

  • In tables that display the counts of categorical variables, we want to mask values for categories whose count is less than 5 (or some other threshold \(T\)).

I’ll call ‘naive masking’ simply changing values less than a threshold by a string (i.e., ‘<5’). We need to go further than this, though. To properly implement masking, there are two requirements:

  • Requirement 1: We need to make sure the value of the masked value can’t be computed from the other values and the totals.
  • Requirement 2: We need to make sure that it’s not possible to exclude some values in the interval [1,T-1]. I.e., for each masked category, all values in the interval need to be possible.

In this doc: First, I go over requirements 1 and 2 in detail. I explain when they are satisfied and how to check they are satisfied. Second, I explore one solution. I think a function can be written that checks if requirements are satisfied and, if the solution is deemed satisfactory, also apply the solution.

2 Requirement 1

Simply put, naive masking does not work whenever the masked values (the unknowns) are computable from known values (totals and other values). Equivalently: whenever the problem can be represented as an equation for which there’s an unique solution.

2.1 Example

cat_value <- c(3, 97, 100)
total <- sum(cat_value)
total
[1] 200

Masking the value 3 (e.g., substituting it by ‘<= 5’) is not enough if we know the other values and the total: 200-97-100 = 3.

2.2 Expressing the problem using an equation

For each categorical variable, the problem can be represented with the equation:

\[ x + y + ... + z = N\]

where \(x,y,...,z\) are known integers representing category counts and \(N\) is the total. We denote masked values (values whose count is less than the threshold) with superscript M (e.g., \(x^M\)).

2.3 Three scenarios where requirement 1 is not satisfied

I came up with 3 scenarios when the exact value is computable from the other counts and the totals.

2.3.1 Scenario 1

Masking only one value without masking another value (or the total)

\[ x + y + ... + z = N\]

If we mask one value (\(x^M\)), this turns into an linear equation with one unknown and thus an unique solution.

\[ x^M = N - y - ... - z \]

(This is the case represented by the first example)

2.3.2 Scenarios 2 and 3: Masking two or more values, but unique solutions still exist

In general, an equation with two or more unknowns has no solution. But given the restrictions (all values are positive integers), there are two special cases where there’s only one possible solution:

2.3.2.1 When all original masked values are one, because one can still work it out from the total.

For instance, we mask two values.

\[ x^M + y^M + ... + z = N\]

If \(x^M = y^M = 1\) then

\[ x^M + y^M = N - ... - z = 2 \]

Even if you don’t know what the original \(x^M\) and \(y^M\) values are, if you know \(N - ... - z\) and the number of masked values (\(\#M\)), the only solution is that all values are 1. This is general always the case when the result of substracting unmasked values from the total is equal to the number of masked values.

2.3.2.2 When all masked values are equal to the highest possible value of the masked values

Assume threshold is 5 (interval is [1,4]).

\[ x^M + y^M + ... + z = N\]

If \(x^M = y^M = 4\) then

\[ x^M + y^M = N - ... - z = 8 \]

Again there’s only one solution for the individual values of \(x^M\) and \(y^M\) (4 for both). So this is equivalent to not masking

2.4 Conclusion

Naive masking won’t work if you can specify the counts as an equation, and it is possible to work out the unknowns (masked values), i.e., the equation has an unique solution.

Possible solution: Frame the problem as a linear equation with one or more unknowns. Try to solve for the unknowns with some R library (or base R), considering restrictions on possible solutions (positive integers). If there’s unique solution to the equation, then there’s no masking.

NB: I am not 100% sure there’re more than the 3 scenarios where naive masking will not work, but I think framing the problem as ‘is there an unique solution to this equation, where the masked values are the unknowns?’ should cover every possibly scenario. As long as we find a way to always answer this question (given restrictions on possible solutions), it should be clear whether Requirement 1 is satisfied or not.

3 Requirement 2: For a masked value, it is impossible to tell anything from the value other than it is less than the threshold

3.1 Problem

  • Typically when we mask, we say a value is less than 5. What we want is to give no other information than that value is an integer in the interval [1,4]. For all category counts, the values 1, 2, 3 and 4 are possible.
  • Sometimes, when applying naive masking, it’s impossible to know the exact value (Requirement 1 is satisfied). However, it is still possible to infer some values from the interval are not possible for a given category count (i.e., the category count has to be 1 or 2, but can’t be 3 or 4)

3.2 Three scenarios

Depending on the information available from the sum of the unmasked values and the total, you can classify all cases in 3 scenarios.

3.2.1 Scenario 1: Always possible to exclude some values in the interval

  • Whenever this is true, you know for sure some values included in the interval are impossible for any category count.

\[ N - w - ... - z < T + \# M - 2 \]

where T is the threshold (i.e. 5), \(\# M\) is the number of ‘Naively masked’ variables, N is the total and w,…,z are the counts for other variables.

3.2.1.1 Example
cat_value <- c(2, 1, 97, 100) 
total <- sum(cat_value)
total
[1] 200

If our threshold is 5, we would mask the values 2 (let’s call it \(x^M\)) and 1 (let’s call it \(y^M\)). But then we know

\[ 200 - 97 - 100 = 3 \]

or

\[ N - z - w = x^M + y^M\]

Even though we want to say that the value for both x and y is \(<5\) (i.e., between 1 and 4), in this example you can tell that for x (or y) it is either 2 or 1. It’s impossible to tell the exact value, because there’s no unique solution. But we know the value is neither 3 nor 4 for any of them.

3.2.2 Scenario 2: Never possible to exclude any variables.

\[ N - w - ... - z = T + \# M - 2 \]

cat_value <- c(3, 2, 97, 100)
total <- sum(cat_value)
total
[1] 202
# we would mask 2 and 3, let's call them x and y
total - 100 - 97
[1] 5

You know one of x or y is not 4, because the sum of both of them is 5. Actually both can’t be 3 either, or one 4 and another 3, etc. But you are saying nothing about the particular values: x could be 5, 4, 3, 2 or 1. Same for y.

You reveal some info: both masked are not close to the threshold. But you can’t tell which one is closer, and all values below the threshold are possible for both counts. This is the info you are giving: at least one of the values is not equal to 4 (or equal to T - 1 in general). But you can’t tell for any specific value whether it is exactly equal to 4 or not.

3.2.2.1 Potential problem

This might seem always ok, but it scales a bit badly. Say that, naively, you would mask 6 values.

cat_value <- c(2,1,1,2,3, 4, 97, 100)
total <- sum(cat_value)
total
[1] 210
total - 100 - 97
[1] 13

Here you know that the sum of the 6 masked values is 13. All values are ‘well masked’, i.e., you can’t tell for any specific value whether it’s 5,4,3,2, or 1. But you are giving away the info that most values are not 5, or 4, or 3. It can be a bit problematic in some edge cases (e.g. there are 10 masked values that add up to 14, you know many values are 1, even if you don’t know which ones).

I’d say we can maybe ignore this problem altogether?

3.2.3 Scenario 3: You may or may not give away some info on the intervals

\[ N - w - ... - z > T + \# M - 2 \] In this case, sometimes you may not be able to exclude any values, but sometimes you will.

3.2.3.1 Example
cat_value <- c(2, 4, 92, 100) 
total <- sum(cat_value)
total
[1] 198

\(198 - 100 - 192 = 6\)

We would mask two values, and we know their sum is equal to 6. If the threshold is 5 (all values are in the interval [1,4]), that makes it impossible that either value is 1. But say you mask 3 categories and the rhs is 8. Then you can’t tell anything about each value.

NB: It’s likely one can find the exact boundaries when this works and when it doesn’t, but I think it’s not necessary because below I explain how to check this more generally.

3.3 Conclusion

You need to make sure that all values in the interval are possible for all values.

I think this is equivalent to having an equation with multiple solutions, where at least one solution per masked count is equal to all values in the interval. E.g., there’s a solution where x^M = 1, one where x^M = 2, one where x^M = 3… and check that for every masked value and possible interval.

Possible way to check requirement 2 is always satisfied: Frame the problem as an equation where masked variables are unknown, and ask ‘Is there at least one possible solution where the unknown takes the value 1, one where the unknown takes the value 2, one where the unknown takes the value 3… for all possible values and unknowns’. Should be possible to program this, and given restrictions (only positive integers), it shouldn’t be too computationally expensive. It may be a bit of a challenge to program this, though.

4 Recap: Function design and possible solution

So far, I have focused on when masking works: under which conditions requirements 1 and 2 are satisfied. The main takeaway is that both requirements can be framed as ‘are solutions to some equation possible’. With this, we can work an algorithm of the form:

  1. Apply naive masking
  2. Check that, after naive masking, requirements 1 and 2 are satisfied [via appropriate equations and their solutions]
  1. If TRUE, table is fine. Naive masking is enough (or there’s no masking).
  2. If FALSE, table is not fine. We need to do something else.
  1. Possibly perform solution (note that even if the solution can’t be automated, we can still write a function checking the requirements are satisfied, potentially saving a lot of time)

4.1 Possible solutions

If naively you would mask only one value, one solution is to interval-mask an additional value (e.g., the second smallest value). It’s easier to reason with an example:

cat_value <- c(3, 97, 100)
total <- sum(cat_value)
total
[1] 200

Here, naive masking is not enough. If you mask 3, you know the value from the totals. A possible solution is to ‘interval-mask’ another value, e.g.,

c('1-4', '99-96', 100)
[1] "1-4"   "99-96" "100"

As far as I know (or well, think), this solution can be expanded to all scenarios irrespective of the number of masked and unmasked values. The algorithm is:

  1. Naive mask.

  2. If requirements are not satisfied, interval-mask another value. Assuming the interval of masked variables is [1,4], the interval for the additionally interval-masked value will be:

\[ [N - \sum Unmasked - \# * 1, N - \sum Unmasked - \# * 4] \] In words: the value of the total minus the sum of the unmasked values mius the number of masked values * 1 is the upper bound of the interval. Same but using 4 is upper bound of interval.

4.1.1 Example

cat_value <- c(1,3,4, 97, 100)
sum(cat_value)
[1] 205
upper.int <- sum(cat_value) - 100 - 3*1
lower.int <- sum(cat_value) - 100 - 3*4

masked.result <- c('<5', '<5', '<5', paste0('[', lower.int, '-', upper.int, ']'), 100)
masked.result                   
[1] "<5"       "<5"       "<5"       "[93-102]" "100"

Since the total is known (205), you know one variable is 100, and all values are possible for the masked: from all equal to 1 (in which case the interval masked value is 102), to all equal to 4 (in which case the interval-masked value is 93).

NB: Choosing the value to smart-mask can be tricky. I would think it should be the smallest unmasked value, but if it’s close to the thresold (e.g., threshold is 6, interval-masked value is 6, the interval could end up being something like, for instance, [4,8], which tells you is definetely not 4 (else it would be masked!)). Choosing this smartly needs some more thought.

4.1.2 Other solutions

Intuitively I chose this solution because I think it’s the solution where we leave as many values unaltered as possible. I haven’t explored other solutions yet. Possible candidates are:

  • Rounding/adding noise: the problem is for this to work, we change every value. We lose a lot of precision. And at least rounding can have weird consequences for requirement 2 (see appendix in Linda’s proposal for rounding).
  • Differential privacy (I heard this but honestly not sure what this is)
  • Merging categories: could be an option too?
  • Exploring what’s there: I found a few resources, of which the most important ones are:
    • This very recent guide on statistical output checking by Health Data & Analytics Research Environments UK programme (people that got a big grant to figure out this and are applying it to many UK research data infraestructures)
    • This R and Python package they seem to be creating an R package. that creates common analysis (e.g., tables or models) with in-built statistical ouput control. Still in-progress and not very well documented yet.

I think exploring this is probably a good idea, but also essentially a full-time job for a few weeks.
